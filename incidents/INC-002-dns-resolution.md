# INC-002 — Сайты не открываются по DNS-именам

> Статус: учебный сценарий. Все результаты команд и действия ниже моделируются для обучения и не являются результатами проверки реального компьютера.

## Обращение пользователя

> «Компьютер подключён к сети, но сайты не открываются по доменным именам».

## Классификация

- Категория: Сеть / DNS
- Приоритет: P3 / Medium
- Влияние: один пользователь не может открывать сайты и пользоваться интернет-сервисами по именам.
- Jira: учебная заявка KAN-5 в проекте IT Service Management.

## Уточняющие вопросы

- Не открываются все сайты или только один домен?
- Работают ли сайты у других пользователей?
- Работают ли приложения, которым нужен интернет?
- Используется ли VPN?
- Что указано в поле DNS Servers в `ipconfig /all`?

## Диагностика и моделируемые результаты

| Проверка | Результат | Интерпретация |
|---|---|---|
| `ipconfig /all` | IPv4 `192.168.1.25`, шлюз `192.168.1.1`, DNS `192.168.1.1` | Компьютер использует шлюз как DNS proxy/relay |
| `ping 192.168.1.1` | Ответы получены | Локальная связь со шлюзом работает |
| `ping 8.8.8.8` | Ответы получены | Доступ до внешнего IP подтверждён |
| `nslookup google.com` | `Request timed out` через `192.168.1.1` | DNS-сервер или DNS proxy по умолчанию не отвечает |
| `nslookup google.com 8.8.8.8` | IP-адрес получен | Публичный DNS доступен и отвечает |

## Интерпретация

Общий доступ во внешнюю сеть работает, но DNS-запрос через сервер `192.168.1.1` не получает ответа. Запрос через `8.8.8.8` выполняется успешно.

Основные возможные причины:

- DNS-сервер, выданный через DHCP, недоступен;
- DNS proxy/forwarder на шлюзе не работает;
- DNS-служба провайдера недоступна;
- DNS-запросы блокируются firewall;
- настройки DNS изменены VPN или статической конфигурацией.

## Как различать уровни неисправности

- Если `ping 8.8.8.8` не проходит, сначала проверяется общий доступ во внешнюю сеть. Это ещё не позволяет сделать вывод только о DNS.
- Если внешний IP доступен, а `nslookup google.com` через `192.168.1.1` завершается тайм-аутом, проблема находится в DNS-сервере или DNS proxy/forwarder, указанном клиенту.
- Если запрос к `8.8.8.8` успешен, а запрос через `192.168.1.1` не работает, это указывает на проблему локального DNS proxy, DNS-сервера провайдера или фильтрацию DNS-запросов. Это не доказывает, что публичный DNS разрешено использовать постоянно.
- Если после очистки кэша результат не меняется, проблема, вероятно, не в устаревшей записи локального кэша.

`ipconfig /flushdns` очищает кэш DNS-клиента Windows. Команда не проверяет доступность DNS-сервера, не исправляет DHCP, DNS proxy или firewall и не меняет адрес DNS-сервера.

## Действия первой линии и эскалация

Специалист первой линии может проверить `ipconfig /all`, доступность шлюза, `nslookup`, наличие VPN и повторить запрос после очистки кэша. Сравнение с публичным DNS допустимо только как временная диагностическая проверка, если это разрешено политикой организации.

На вторую линию или сетевому администратору нужно передать заявку, если:

- DNS-сервер, выданный через DHCP, не отвечает нескольким пользователям;
- DNS proxy/forwarder на шлюзе требует настройки или перезапуска;
- необходимо менять DHCP, firewall, DNS-фильтрацию или корпоративные DNS-зоны;
- публичный DNS работает, но корпоративные имена не разрешаются;
- проблема сохраняется после проверки клиента и затрагивает несколько устройств.
## Моделируемая причина

DNS-сервер, назначенный через DHCP, не отвечал на запросы. В учебном сценарии в настройках подключения был указан доступный DNS-сервер.

Важно: `ipconfig /flushdns` очищает локальный DNS-кэш Windows, но не меняет DNS-сервер и не исправляет сам DNS-сервис.

## Моделируемое решение

1. Указать доступный DNS-сервер в настройках сетевого подключения.
2. Очистить локальный DNS-кэш:

   ```cmd
   ipconfig /flushdns
   ```

3. Проверить разрешение имени:

   ```cmd
   nslookup google.com
   ```

4. Проверить открытие сайтов по доменным именам.

## Проверка восстановления

- `ping 8.8.8.8` — ответы получены;
- `nslookup google.com` — IP-адрес получен;
- сайты открываются по доменным именам;
- DNS-разрешение работает.
